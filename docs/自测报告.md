### 2. 端到端自测（真实子进程：FastAPI 上游 + 两个转发器实例）

```text

```

关键实测耗时（本机 loopback）：

| 场景 | 实测 |
| --- | --- |
| 8 个并发到期查询收到 TTL=0 旧址 | 各 99–103ms，整批 wall=104ms |
| 上游实际收到同域名包数 | **1**（single-flight） |
| 250ms 延迟回源在后台成功后续缓存 | 再查 TTL=29（新 TTL=30） |
| 300ms 延迟期间改答，后台回包刷新 | 先 101ms TTL0 旧址，随后新 IP TTL=29（0.5ms） |
| 停答后单个旧址查询 | **101.3ms** 返回旧 IP、TTL=0 |
| 恢复并改新址后查询 | **1.4ms** 返回 198.51.100.77 |
| 从无旧址 + 停答 → SERVFAIL | **1001.0–1002.0ms** |
| 短限时实例（400ms）SERVFAIL | **401.4ms** |
| NXDOMAIN 后再停答 → SERVFAIL（旧址已清） | NXDOMAIN 1.3ms，随后 401.4ms |
| grace=1s 且已过期 2.2s → 不用旧址 | 401.5ms 后 SERVFAIL |
| 新鲜缓存第二次查询的上游包增量 | 0 |
| dnspython 带 EDNS OPT 的 A/AAAA 报文 | NOERROR+IP / REFUSED，互通正常 |
| 非法 IP 调 API | HTTP 422 |

## 三、未完成项 / 已知限制（如实说明）

1. **未在本沙箱真正 `docker compose up --build`**：环境中没有 docker CLI/daemon、
   无 `/var/run/docker.sock`、无 root/sudo，无法运行容器。已完成：
   Compose v2.29.7 `config` 校验通过；Dockerfile 基于 `python:3.11-slim` +
   常规 pip 依赖；两个入口（`python -m app.upstream/forwarder`）均以真实子进程
   在等价环境反复实测。首次主机构建仍需在有 Docker 的机器上验证网络拉取。
2. 沙箱禁止向子进程 `kill(2)`（父进程 terminate 也 EACCES）。为此仅在
   `EXIT_ON_STDIN_EOF=1` 时启用 stdin-EOF 自杀看门狗（`app/runtime.py`），
   **Compose/Docker 不设置该变量，不影响生产路径**；E2E 脚本优先 SIGTERM，
   被沙箱拒绝时关闭 stdin 让进程自退，已验证无新增残留进程。
3. 环境无 `dig`/`nslookup` 且无法 root 安装 dnsutils，因此 README 中的 dig
   输出为按实际报文给出的期望样式；线路兼容性改用 dnspython（含 EDNS OPT）实测，
   并通过自带 `scripts/dns_client.py` 完成全部功能验证。
4. 协议范围：仅 UDP、仅 A/IN；其它 qtype/class 统一 `REFUSED`（策略选择，
   若希望对 AAAA 回 NOERROR 空应答，改 `forwarder.py` 中对应分支即可）。
5. 未实现 TCP/53、DNSSEC、完整 CNAME 链解析、AAAA 转发；多 A 记录支持，
   缓存有效期取各记录 TTL 的最小值。
6. NXDOMAIN 立即删旧址且不做负 TTL 缓存；NODATA（NOERROR 无 A）透传空应答、
   不清旧址、不缓存。题目只明确要求 NXDOMAIN 清旧址，故采取这一保守语义。
7. 单进程 asyncio，面向演示与小规模内网；未做源 IP ACL、限速、TCP 兜底、
   多上游故障切换、指标导出等生产加固。
